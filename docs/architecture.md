# Архитектура

## Компоненты

Один Worker на среду (`otklikator` — staging, `otklikator-prod` — прод) обслуживает и HTTP, и Cron.

```
                 ┌──────────── Cloudflare Worker (Hono, TypeScript) ────────────┐
 браузер ──HTTP──▶ fetch: лендинг, вход, кабинет, анкета, подбор, Stripe-вебхук    │
                 │ scheduled (*/20): фиды → дедуп → скоринг → matches            │
                 └───┬─────────┬──────────┬──────────┬───────────┬──────────────┘
                     │         │          │          │           │
                    D1        R2       Resend     Stripe     OpenRouter
               (все данные) (файлы CV) (письма) (оплата)  (разбор CV, GLM)
```

| Часть | Зачем | Где в коде |
|---|---|---|
| Cloudflare Workers + Hono | маршруты, HTML-страницы, Cron | `src/index.ts`, `src/views.ts` |
| D1 (SQLite) | пользователи, сессии, подписки, CV-метаданные, анкеты, вакансии, совпадения, состояние фидов | `migrations/` |
| R2 | оригиналы CV (бакеты `otklikator-cv`, `otklikator-cv-prod`, binding `CV_BUCKET`) | `src/lib/cv.ts` |
| Cron Trigger `*/20 * * * *` | сбор вакансий и подбор | `src/lib/jobs/pipeline.ts` |
| Resend | письмо входа, письмо о неудачной оплате, письмо о сбое фидов | `src/lib/email.ts` |
| Stripe | Checkout (подписка), Customer Portal, вебхуки; Managed Payments | `src/lib/billing.ts` |
| OpenRouter | автозаполнение анкеты по тексту CV и письма-отклики, модель `OPENROUTER_MODEL` (`z-ai/glm-5.3`) | `src/lib/llm.ts`, `src/lib/profile.ts`, `src/lib/letters.ts` |

Зависимости: `hono`, `stripe`, `zod` (схема анкеты), `unpdf` (pdf.js для текста PDF), `fflate` (распаковка DOCX).
Тесты: vitest с `@cloudflare/vitest-plugin` (Miniflare + D1), `npm test`. npm ставится с `legacy-peer-deps` (`.npmrc`).

## Маршруты

| Метод и путь | Что делает |
|---|---|
| `GET /` | лендинг с формой email (вошедших перекидывает в `/app`) |
| `GET /terms`, `GET /privacy` | условия и политика (нужны Stripe для live-режима) |
| `POST /auth/start` | создать пользователя при необходимости, отправить magic link |
| `GET /auth/verify?token=` | погасить токен, подтвердить email, поставить cookie сессии |
| `POST /auth/logout` | удалить сессию |
| `GET /app` | кабинет: подписка, анкета, число новых совпадений |
| `GET /app/profile`, `POST /app/profile` | анкета: показать, сохранить правки (`source=user`) |
| `POST /app/cv` | загрузить CV → R2 → автозаполнение анкеты |
| `POST /app/profile/refill` | заполнить анкету заново по последнему CV |
| `GET /app/cv` | скачать последнее загруженное CV |
| `GET /app/matches`, `POST /app/matches/:seq/hide` | подходящие вакансии, «Не подходит» |
| `GET /app/matches/:seq` | вакансия, причины, письмо-отклик (с подпиской) или кнопка подписки |
| `POST /app/matches/:seq/letter` | написать (или переписать) черновик письма моделью; только с активной подпиской |
| `POST /app/matches/:seq/application` | сохранить правки: кому, тема, текст |
| `POST /app/matches/:seq/sent`, `POST /app/matches/:seq/skip` | «Я отправил(а)» → `applied`; «Пропустить» → вакансия скрыта |
| `POST /billing/checkout`, `POST /billing/portal` | редирект в Stripe Checkout / Customer Portal |
| `POST /stripe/webhook` | вебхук Stripe (без сессии, проверка подписи) |

Всё под `/app` и `/billing` требует сессию. Необработанные ошибки логируются (`[error] METHOD path: ...`),
человеку показывается понятная страница ошибки.

## Вход и сессии (`src/lib/auth.ts`)

- Токен входа — случайная строка в ссылке, в `login_tokens` хранится только её sha256. Живёт 24 часа, гасится один раз.
- Сессия — cookie `HttpOnly`, `SameSite=Lax`, `Secure` на https, 30 дней. В `sessions` тоже только sha256 id.
- Защита от спама чужих ящиков: не больше одного письма входа в минуту на адрес (`RESEND_COOLDOWN`).

## Оплата (`src/lib/billing.ts`)

- `POST /billing/checkout`: Checkout Session в режиме `subscription` с `STRIPE_PRICE_ID`, `client_reference_id`
  и `subscription_data.metadata.user_id` = id пользователя; `customer`, если уже есть, иначе `customer_email`.
- Вебхук проверяет подпись (`STRIPE_WEBHOOK_SECRET`), id события пишет в `stripe_events`, чтобы повторная доставка
  не обработалась дважды. Обрабатываемые события: `checkout.session.completed`, `customer.subscription.created`,
  `customer.subscription.updated`, `customer.subscription.deleted`, `invoice.payment_failed`
  (последнее шлёт письмо «обновите карту»).
- Источник правды о доступе — таблица `subscriptions` (последнее состояние из вебхуков). Доступ есть при статусе
  `active` или `trialing`. Stripe API на каждый запрос не дёргается.
- `current_period_end` берётся с позиции подписки (новые версии API) или с самой подписки (старые).

## CV и анкета (`src/lib/cv.ts`, `src/lib/profile.ts`)

1. Тип файла определяется по содержимому (`%PDF-` или zip `PK`), не по расширению; лимит 5 МБ.
2. Текст достаётся в воркере: PDF через pdf.js (`unpdf`), DOCX из `word/document.xml`. Меньше 200 символов текста —
   считаем сканом и не разбираем.
3. Оригинал кладётся в R2, метаданные — в `resumes`.
4. В OpenRouter уходит только текст CV, ответ — JSON по строгой JSON-схеме, затем проверка zod (`ProfileSchema`).
5. После модели имя, город, контакты и компании сверяются с текстом CV, чего в тексте нет — выбрасывается.
6. Поля, которые человек задаёт сам (формат, зарплата, «не предлагать»), при повторном разборе сохраняются.
7. Без `OPENROUTER_API_KEY` или при сбое модели CV всё равно сохранён, причина пишется в `profiles.parse_error`
   и показывается человеку.

## Схема D1

| Таблица | Миграция | Что хранит |
|---|---|---|
| `users` | 0001 | email, когда подтверждён, `stripe_customer_id` |
| `login_tokens` | 0001 | sha256 токенов входа, срок, когда использован |
| `sessions` | 0001 | sha256 id сессий, срок |
| `subscriptions` | 0001 | последнее состояние подписки Stripe (`status`, `price_id`, `current_period_end`, `cancel_at_period_end`) |
| `stripe_events` | 0001 | обработанные события вебхука (идемпотентность) |
| `resumes` | 0002 | метаданные CV, ключ в R2 |
| `profiles` | 0002 | анкета JSON, `source` (`ai`/`user`), `parse_error` |
| `vacancies` | 0003 | вакансии из фидов; `seq` — курсор подбора, `id` = `<источник>:<id>`, `fingerprint` — дедуп между источниками, `flags` (`REMOTE WORLD US_ONLY CONTRACT CY`) |
| `matches` | 0003 | совпадения пользователь × вакансия: балл, причины, статус `new`/`hidden`/`applied` |
| `match_state` | 0003 | до какой вакансии посчитан подбор и для какой версии анкеты |
| `feed_state` | 0003 | курсор старой схемы обхода; с PR #5 не используется (заменён `feed_sources`) |
| `feed_runs` | 0003 | журнал опросов источников (неделя) |
| `feed_sources` | 0004 | расписание и здоровье каждого источника |
| `applications` | 0005 | письмо-отклик на пару человек × вакансия: адрес, тема, текст, статус `draft`/`sent`/`skipped`, канал, непроверенные цифры |

## Конвейер вакансий на Cron (`src/lib/jobs/pipeline.ts`)

`scheduled` вызывает `runJobsCron` в `ctx.waitUntil`. За один запуск:

1. **Сбор (`collect`).** Берёт источники, у которых подошёл срок и нет паузы, самые «просроченные» первыми,
   не больше `MAX_FEEDS_PER_RUN = 12`, по 6 параллельно. Подробности расписания — в [feeds.md](feeds.md).
2. **Сохранение (`saveVacancies`).** Пачкой через `json_each`: новые вставляются, известные (по `id` или
   `fingerprint` — нормализованные «компания|должность») получают свежий `last_seen_at`. Вакансии старше
   14 дней (`FRESH_DAYS`) из фидов не берутся.
3. **Письмо о сбоях.** Если источник только что упал третий раз подряд — одно письмо на `ALERT_EMAIL`.
4. **Подбор (`matchUsers`).** До 100 подтверждённых пользователей с анкетой за запуск, давно не считанные первыми.
   Каждому — вакансии после его курсора (`match_state.last_seq`). Если анкета изменилась или это первый раз —
   пересчёт по всем свежим вакансиям (14 дней), несмотренные совпадения (`new`) удаляются, скрытые и
   отправленные остаются. Не больше 2000 вакансий за запуск и не больше 3 новых совпадений от одной компании.
5. **Очистка (`cleanup`).** Вакансии, пропавшие из фидов больше 45 дней назад, удаляются вместе с несмотренными
   совпадениями; `feed_runs` старше недели удаляются.
6. В лог пишется строка `[jobs] feeds=… new=… users=… scored=… matched=… errors=…`.

## Скоринг (`src/lib/jobs/score.ts`)

Детерминированный, без модели: дёшево считать для каждого пользователя по каждой новой вакансии, и можно показать
причины. Это обобщение `jobslib.score` и `triage.py` из PoC: там правила были зашиты под одного кандидата,
здесь их задаёт анкета.

- Должность относится к семейству ролей (backend, fullstack, frontend, mobile, devops, data, ml, qa, solutions,
  pm, project, design, eng_manager, nontech, eng). Семьи человека — из целевых ролей и заголовка анкеты, плюс соседние
  (например, backend → fullstack, solutions).
- В балл 0–100 идут роль, стек, грейд, локация и формат, контракт/частичная занятость, свежесть.
  Порог показа `MIN_SCORE = 35`.
- Принцип PoC «по умолчанию откликаемся»: нехватка лет, другой домен или зарплата ниже — не повод отсекать.
  Отсекаются только «не предлагать» из анкеты, чужая роль или язык, US-only, офис в другой стране (если человек
  не готов к переезду) и стажировки для опытных.

## Письма-отклики (`src/lib/letters.ts`)

- Доступны только при активной подписке (`hasActiveSubscription`); подбор вакансий — для всех.
- Модель пишет только смысл: 3–4 предложения «деталь о компании из вакансии → кейс с цифрой из анкеты → предложение созвона».
  Приветствие («Hi <Company> team,» / «Здравствуйте!») и подпись (имя + до двух контактов) собираются кодом из анкеты.
  Язык письма — язык вакансии (доля кириллицы).
- В модель уходят анкета без контактов (имя, заголовок, стек, опыт, факты) и вакансия (до 3000 символов текста).
- Цифры из письма сверяются с анкетой и вакансией. Если есть лишние — одна повторная попытка с подсказкой,
  если и там есть — письмо сохраняется, а человеку показывается «Проверьте цифры …».
- Адрес для отклика ищется в тексте вакансии (`findApplyEmail`): jobs@/careers@/hr@ и адреса рядом со словами
  «apply / send CV / присылайте резюме» в приоритете, noreply/privacy/картинки отбрасываются. `cleanHtml` оставляет
  адрес из `mailto:` в тексте. Нет адреса — человек откликается через форму на сайте или вписывает адрес сам.
- Отправка пока ручная: «Открыть в почте» (`mailto:`), затем «Я отправил(а)». Gmail — PR 9.
- Правило «одна компания раз в 2 недели» (`COMPANY_COOLDOWN_DAYS`, ключ компании как в fingerprint): на странице
  вакансии предупреждение, если отклик в ту же компанию уже уходил.
- Не больше `DAILY_LETTER_LIMIT = 30` черновиков на человека в сутки.
